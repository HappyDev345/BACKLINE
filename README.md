# BACKLINE

BACKLINE is a frontend-first community prototype for the people who make live
events, film, music and photography happen. It is built with React and Vite;
Supabase integration is retained for a future full-stack phase.

## Run the prototype

Requirements: Node.js 18+.

```bash
npm install
npm run dev
```

Without both `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, the app runs in
**preview mode** with sample projects, crew, posts, discussions, messages and
notifications. You can sign in with a valid email and a password of at least
six characters to try the interactive flows. Preview changes live in memory
and reset when you refresh; they are not sent to Supabase.

Check the production bundle with:

```bash
npm run build
```

## Later: connect Supabase

When you are ready to test the full-stack flows:

1. Create a separate Supabase project for development or preview testing.
2. Run `supabase/schema.sql` in that project's SQL Editor.
3. Create a local `.env` file with the project's URL and public anon key:

   ```env
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_ANON_KEY=your-anon-public-key
   ```

4. Restart Vite. When both values are present, the app uses Supabase instead of
   preview mode.

In connected mode, the public landing page's Featured live productions section
shows the three newest public projects from Supabase. Preview mode keeps its
illustrative sample cards.

Never put a Supabase service-role key in the frontend or commit credentials.
Use a separate project and environment variables for preview deployments so
test data cannot affect production.

### Supabase Auth and security setup

- In Supabase Auth settings, enable the Email provider and allow user sign-ups if
  visitors should be able to create accounts. Configure the project's site URL
  and allowed redirect URLs for both the Vercel deployment and local development.
- Set a suitable password policy and decide whether email confirmation is
  required. New connected-mode accounts require at least 12 characters in the
  form; set the Supabase password policy to match. These are Supabase Auth
  settings, not database schema settings.
- Profile photos are intentionally public. The `media` bucket permits public
  reads, while uploads are restricted to a folder named for the authenticated
  user's ID, JPEG/PNG/WebP formats, and 5 MB.
- Messages are not end-to-end encrypted. Row-level security restricts them to
  conversation members. The direct-conversation RPC creates/reuses a
  two-person conversation; clients cannot add themselves to existing
  conversations directly.
- If the schema was already applied to a Supabase project, run
  `supabase/migrations/20261026_secure_direct_conversations.sql` in that
  project's SQL Editor before using messaging. For a new project, the updated
  `supabase/schema.sql` includes these policies and functions.

## Hosting direction

For an eventual small full-stack launch, staying with **Vercel for the React
site and Supabase for Auth, Postgres, Storage and Realtime** is a straightforward
low-cost setup. The current frontend is already deployed on Vercel, so there is
no need to move hosting just to add Supabase. Both providers' free-tier quotas,
pausing rules and feature limits can change; check the current terms and expected
usage before depending on the free plans. A custom domain can wait until the
product is closer to launch.

## Project structure

```text
src/
  App.jsx                 Routes and shared auth modal
  components/             Navigation, cards and modals
  context/                Auth and in-memory preview data
  lib/                    Supabase client, demo fixtures and helpers
  pages/                  Landing, feed, discover, people and community pages
supabase/
  schema.sql              Database schema and policies for the later backend
```

## What the setup files do

- `index.html` is the small web page that loads the React app into the browser.
- `vite.config.js` tells Vite how to prepare the React app for local work and hosting.
- `package.json` lists the libraries the app uses and the commands such as `npm run dev`.
- `package-lock.json` is generated by npm to keep installed library versions consistent; it is not hand-edited.
- `README.md` is this human-readable setup and project guide.

JSON files such as `package.json` and `package-lock.json` do not support comments.
Their purpose is explained here instead; images are artwork rather than readable
source code.
